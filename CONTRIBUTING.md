# Contributing

Useful contributions make a specific research contract more reliable or easier to reuse: a reproducible bug report, an edge-case test, clearer methodology, or an independently testable adapter.

Before proposing a change, read the relevant implementation and its limitations. Include a minimal synthetic fixture, the expected behavior, actual behavior, and environment versions. Avoid account details, private datasets or live credentials in issues and test cases.

Run `python -m pytest -q` and the documented demo before submitting. Changes to signal timing, indicator initialization, result identity or execution rules need explicit tests and documentation. Do not make a metric look better by silently changing its meaning.

Contribution discussions should focus on verifiable software behavior rather than trading-return claims. Contributors must have the right to publish their changes under the project license. VBT Pro and other vendor source code must not be submitted.
